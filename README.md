# HOMEi

אפליקציית ווב (Next.js 16) למעקב אחרי חשבונות הבית: חוזים, חיובים, מבצעים שנגמרים והשוואה להצעות. המסך הראשי הוא דירה בחתך שבה כל חדר מייצג חשבונות.

- **כניסה:** אימייל וסיסמה, ובכל מכשיר חדש קוד בן 6 ספרות שנשלח למייל. יש גם איפוס סיסמה בקוד.
- **נתונים:** Supabase (Postgres + RLS + אחסון פרטי). כל שורה וכל קובץ נגישים רק לבני אותו משק בית.
- **סריקה:** Claude API קורא חוזה, חשבונית או הצעת מחיר ומחלץ ספק, מחיר, סיום מבצע וקנס יציאה.
- **שיתוף:** מנהל/ת הבית מזמין/ה בני משפחה לפי כתובת מייל. הקישור בתוקף 7 ימים ועובד רק לכתובת שהוזמנה.
- **מעקב תקופתי:** Vercel Cron רץ פעם ביום, יוצר התראות ושולח תקציר במייל.

## הקמה (פעם אחת)

### 1. Supabase
1. צרו פרויקט ב-[supabase.com](https://supabase.com). מומלץ לבחור אזור באירופה (למשל Frankfurt).
2. **SQL Editor:** הדביקו והריצו לפי הסדר את `supabase/migrations/0001_init.sql`, `0002_password_auth.sql` ו-`0003_grants.sql`. זה יוצר את הטבלאות, הרשאות RLS ואת ה-bucket הפרטי `documents`.
3. **Authentication → Sign In / Providers → Email:** ודאו שהספק מופעל.
   - "Confirm email" לא משנה כאן: האפליקציה יוצרת את המשתמש בשרת ומאמתת את המייל בעצמה בקוד בן 6 ספרות לפני כל גישה.
   - מומלץ: Minimum password length 10, ואם זמין בתוכנית שלכם, להפעיל Leaked password protection.
4. **Authentication → URL Configuration:** Site URL = `https://YOUR-APP.vercel.app`.
5. **Project Settings → API:** העתיקו את `URL`, את מפתח ה-`anon` ואת מפתח ה-`service_role`.

### 2. מייל (Resend)
1. צרו חשבון ב-[resend.com](https://resend.com) ואמתו דומיין שולח.
2. צרו API key. הוא משמש לקודי אימות, לאיפוס סיסמה, להזמנות ולתקציר ההתראות.
   בלי מפתח, בסביבת פיתוח הקוד מודפס ללוג של השרת. בפרודקשן חייבים מפתח.

### 3. Claude API
צרו מפתח ב-[platform.claude.com](https://platform.claude.com). ברירת המחדל היא `claude-sonnet-5-5`, ואפשר לשנות דרך `ANTHROPIC_MODEL`.

### 4. Vercel
1. Import את הריפו ב-[vercel.com/new](https://vercel.com/new).
2. ב-Environment Variables הוסיפו את כל המשתנים מ-`.env.example`:
   - `DEVICE_COOKIE_SECRET` ו-`CRON_SECRET`: צרו ערכים אקראיים עם `openssl rand -base64 48`.
   - `NEXT_PUBLIC_SITE_URL`: כתובת האתר הסופית.
3. Deploy. ה-Cron מוגדר ב-`vercel.json` לפעם ביום. Vercel שולח אוטומטית `Authorization: Bearer $CRON_SECRET`.

## פיתוח מקומי
```bash
cp .env.example .env.local   # מלאו ערכים
npm install
npm run dev
```

## אבטחה ופרטיות
- **RLS על כל טבלה.** טבלאות הקודים והמכשירים נגישות רק מהשרת עם service role.
- **התפקידים נאכפים במסד הנתונים.** אין למשתמשים מדיניות `insert`/`update` על `household_users`, ולכן אי אפשר להעלות הרשאות. הצטרפות מתבצעת רק דרך הזמנה שנבדקת בשרת.
- **סיסמאות:** מנוהלות ב-Supabase Auth (hash עם bcrypt), מינימום 10 תווים. הודעת שגיאה אחידה בכניסה ובאיפוס, כדי שלא אפשר לגלות אילו מיילים רשומים.
- **קוד האימות:** נשמר כ-hash עם סוד, בתוקף 10 דקות. מותרים 5 ניסיונות לכל קוד ו-5 שליחות בשעה.
- **איפוס סיסמה:** קוד במייל (15 דקות, עד 3 בשעה). אחרי איפוס כל המכשירים המאומתים מנותקים.
- **מכשיר מאומת:** עוגייה חתומה (HMAC, httpOnly) ל-30 יום, ובנוסף רשומה בטבלה שאפשר לבטל מההגדרות.
- **קבצים:** נשמרים ב-bucket פרטי בנתיב `<household_id>/...`. צפייה רק דרך קישור חתום ל-2 דקות.
- **חיסוי:** מספרי ת״ז וכרטיסי אשראי מושחרים בשדות שנשמרים מהסריקה. הקובץ המקורי נשמר כפי שהועלה.
- **כותרות אבטחה:** CSP, HSTS, `frame-ancestors 'none'`. ה-`robots` מוגדר noindex.

## לפני השקה: לא לדלג
- **ייעוץ משפטי:** מדיניות פרטיות מלאה (`app/privacy` הוא טיוטה), ובדיקת חוק הגנת הפרטיות ותקנות אבטחת מידע, כולל רישום מאגר אם נדרש.
- **מקדמי הצריכה הצפויה** של מים וחשמל ב-`lib/bills.ts` הם ערכי דוגמה. צריך לכייל אותם לפי ממוצעים בישראל.
- **מחירי שוק:** טבלת `market_offers` מתמלאת ידנית או מסקריפט שתכתבו (service role). אין עדיין איסוף אוטומטי מאתרי הספקים.
- **תנאי השימוש בנתונים של Anthropic:** לבדוק ולציין למשתמשים.
- **מעבר לאייפון בהמשך:** אותו Supabase ישמש אפליקציית Expo/React Native.
